Technical Architecture & Execution Model

PyPad operates on a client-server architecture designed for speed, isolation, and minimal footprint:

  • Server-Side Execution: Python scripts do not execute on your local device hardware. When you click Run, the code is sent to the PyPad host server, where an isolated Python subprocess executes it.
  • Zero npm Dependencies: The backend is powered purely by Node.js built-in modules, eliminating external dependency vulnerabilities.
  • Ephemeral Sandbox Runner: On the host server, scripts are placed in temporary directories (/tmp/...) that are automatically wiped after execution. Subprocesses run under python3 -I -B -q -u with strict CPU timeouts and ulimit memory caps.
  • Pre-Execution Code Validator: An in-memory AST analyzer (validator.js) checks code before launch on the host server, blocking OS manipulation, process creation, and external network socket connections.
  • Live Streaming Console: Terminal output (stdout, stderr) and interactive input (stdin) stream between your browser and the server subprocess in real time via Server-Sent Events (SSE).
  • Protected Server Workspaces: Saved workspace files reside in isolated server directories safeguarded by path traversal protection (safePath) and per-user storage caps.
