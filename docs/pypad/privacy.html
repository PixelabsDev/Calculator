Privacy Policy for PyPad

Effective Date: November 1, 2026  |  Service: PyPad (Mobile Py IDE)  |  Publisher: Pixelabs Digital Services

Server-Side Execution Model: PyPad is a web-based IDE where Python code executes remotely on the host server running the PyPad backend—not on your client device or phone. We do not permanently store executed scripts, monetize user code, or track user activity.

1. Overview

PyPad is developed by Pixelabs Digital Services ("Pixelabs", "we", "us") as a lightweight web development environment accessible from any modern mobile or desktop web browser. This Privacy Policy details how code payloads, terminal streams, and server workspace files are handled when you use PyPad.

2. Information We Do Not Collect

  • No Mandatory Accounts: You do not need to register, provide an email address, or submit personal identification to write and run code.
  • No Permanent Code Archiving: We do not store, index, sell, or train machine-learning models on the code you execute.
  • No Third-Party Analytics: PyPad does not load third-party advertising SDKs, tracking pixels, or user-profiling beacons.
  • No Cross-Site Surveillance: We do not track your browsing activity across other websites or services.

3. Server-Side Code Execution & Stream Handling

When you click Run or type code in PyPad:

  • Remote Server Execution: Your Python script is transmitted securely via HTTPS to the host server where the PyPad backend is deployed. Execution occurs on the host server's CPU inside a dedicated Python subprocess.
  • Ephemeral Execution Sandbox: On the host server, scripts are written to a temporary directory (/tmp/...) that exists exclusively for the duration of the execution. As soon as the script completes, encounters an error, or reaches its execution timeout, the temporary file is immediately and permanently deleted from the server.
  • Live Streaming Data: Terminal outputs (stdout and stderr) and real-time interactive input (stdin) are streamed directly between your browser and the server subprocess via Server-Sent Events (SSE) and WebSockets. These real-time streams are held in volatile memory and are not logged to disk.
  • Subprocess Containment & Security: Server-side subprocesses run under python3 -I -B -q -u with strict CPU timeouts, memory caps (ulimit), and blocked external network sockets.
  • In-Memory AST Safety Check: Prior to execution, the server's AST validator (validator.js) checks the code in volatile memory to ensure it does not attempt unauthorized operating system or socket operations. The code is never persisted during this verification.

4. Server Workspace Storage

If you utilize PyPad's persistent workspace feature to save project files:

  • Your files are stored in an isolated, sandboxed directory on the host server.
  • Workspaces are protected against directory traversal through path sanitization (safePath) and enforced storage quotas (perUserLimitBytes).
  • An automated background cleaner sweeps inactive or expired temporary workspace buffers.
  • You can download, inspect, or delete your workspace files directly from the Files panel in your browser at any time.

5. Infrastructure & Security Headers

PyPad is delivered with hardened web security headers:

  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Referrer-Policy: no-referrer

Standard edge network logs (such as timestamps, IP addresses, and HTTP status codes) are maintained temporarily by edge CDN providers solely for threat mitigation, rate limiting, and security compliance.
