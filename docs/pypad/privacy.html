Privacy Policy for PyPad

Effective Date: November 1, 2026  |  Service: PyPad (Mobile Py IDE)  |  Publisher: Pixelabs Digital Services

Privacy Commitment: PyPad is a sandboxed Python IDE designed with zero telemetry. We do not track users, log private code to databases, sell personal data, or bundle advertising SDKs.

1. Overview

PyPad is developed by Pixelabs Digital Services ("Pixelabs", "we", "us") to provide a lightweight, browser-accessible Python coding environment for mobile devices and desktop computers. This Privacy Policy details how code, execution streams, and workspace files are handled by the PyPad backend.

2. Information We Do Not Collect

  • No Mandatory Personal Identification: You are not required to provide your name, phone number, physical address, or payment details to use PyPad.
  • No Permanent Code Archiving: We do not index, analyze, train AI models on, or store executed script code in persistent backend log databases.
  • No Third-Party Analytics or Trackers: PyPad contains zero tracking pixels, zero analytics SDKs, and zero advertising beacons.
  • No Cross-Site Fingerprinting: We do not track your activity across other websites or services.

3. Code Execution & Data Flow

When you execute a Python script or interact with the REPL console:

  • Ephemeral Execution Sandbox: Your code is written to an isolated temporary file in system temp space (/tmp/...) solely for the duration of the execution. Once the process completes, errors, or reaches its timeout, the temporary file is immediately and permanently deleted.
  • Live Streaming Streams: Standard output (stdout), error output (stderr), and interactive inputs (stdin) are streamed in real time over HTTPS using Server-Sent Events (SSE) and WebSockets directly between your browser and the spawned Python subprocess. These terminal streams are not logged to disk.
  • Subprocess Containment: Python processes run under python3 -I -B -q -u with strict CPU timeouts and ulimit memory limits. The runner blocks raw network socket calls to prevent external connections.
  • Pre-Execution Code Validator: PyPad's built-in AST validator (validator.js) verifies code in volatile memory prior to execution solely to enforce safety boundaries (e.g., preventing OS-level tampering). The code is not stored during this check.

4. Workspace Storage

If you utilize PyPad's workspace feature to save scripts and assets:

  • Files are stored within a dedicated, isolated workspace directory on the server.
  • Workspaces are constrained by storage quotas (perUserLimitBytes) and protected by path sanitization (safePath) to prevent directory traversal.
  • An automated background sweeper cleans inactive or expired temporary workspace buffers.
  • You can download, view, or permanently delete your workspace files directly through the Files panel at any time.

5. Infrastructure & Security Headers

PyPad delivers strict web security headers to protect your session:

  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Referrer-Policy: no-referrer

Standard server request logs (such as request timestamps and HTTP status codes) are maintained temporarily for system diagnostics and rate-limiting enforcement, and contain no script payload data.
